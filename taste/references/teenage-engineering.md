# Teenage Engineering

**Tags:** `precise-technical` `instruments` `labels` `inspection` `object` `diagram`

The instruments, and the pages that let you inspect them. Not a fashion campaign, and not a single homepage skin. Public captures of teenage.engineering do not agree with each other, so this file records no hex, no radius, and no type measurement.

## Description

Machines with every control labeled. A synthesizer, a recorder, a mixer: keys, encoders, and ports in rows, each with a name or a small pictogram, color on the hardware used as a code rather than as decoration. The website's useful pages put that object where you can study it. A picture of the machine, a name, a short technical fact, a way to move to the next part. One capture of the homepage describes a full-bleed monochrome photograph and a hairline navigation. Another describes a light editorial mode and a dark product mode. The homepage is allowed to change. The inspection is the reference.

## Key decisions

- The object is a device you read, not a garment you admire (`product.direction-serves-job`).
- Labels name parts. They do not praise the brand (`uniqueness.specific-copy`).
- The picture is straight enough that a control can be found on it. Atmosphere is secondary to identification (`material.image-or-type`).
- Navigation can be diagrammatic, a mark plus a word, as long as the word is there (`a11y.names`).
- Color, when the hardware uses it, means a function. It is not a gradient on the page (`color.semantic-quiet`).

## Why it works

Someone on this page is trying to understand a physical interface. A campaign photograph of a person in a city answers a different question, which is why COS is a different reference. Naming the part and showing it at a readable scale is the hierarchy (`hierarchy.three-levels`). The page can stay quiet because the machine is already visually dense. Adding cards around each specification would double the chrome (`material.no-nested-cards`).

## What to steal

- One object, large, with callouts or a spec list that shares the object's alignment.
- Labels in the same voice as the hardware: short, literal, sentence case or a consistent case, never a pile of badges.
- A second view only when it shows a different fact (a port, a dimension, a screen), not a second mood.
- Technical facts in a column or a definition list: name, then value. Tabular figures where the values are numbers (`type.numbers`).

## What not to copy

- Hairline-weight type at a size used for navigation decoration. If a capture shows very light, very small labels, that fails `a11y.size` and often fails contrast. Keep the diagrammatic idea and set the label so it can be read.
- Their pictograms as a general icon library for a SaaS app. A mark that means "this product section" is not a universal action icon.
- A monochrome store photograph as a theme. One homepage capture is not a token set.
- Rounded or square corners from a single write-up. The captures disagree. Decide from the object.
- COS's campaign structure with these products swapped in. A model in a building is not an inspection.

## Uniqueness

COS, in quiet luxury, frames a garment on a person and captions it. Aesop writes a label for a bottle. Figma is software chrome beside a canvas. Teenage Engineering is the precise reference for a physical machine: the page behaves like a plate in a manual. Use it when the user is trying to see how a thing is built. Use COS when the user is trying to see how a thing looks on a body.

## Product fit

Hardware, instruments, tools, a product page whose buyer needs parts and dimensions, a spec beside a photograph.

A poor fit for a magazine essay, a night listing, or a writing column. Also a poor fit for a lifestyle campaign. If the photograph is the only argument, load COS instead.
