# Example tokens

Four sample identities in the [DESIGN.md](https://github.com/google-labs-code/design.md) format (`version: alpha`). They are examples of directions that have already been chosen. They are not the taste layer.

| File | Direction | Name | When to load it |
| --- | --- | --- | --- |
| `quiet-luxury.DESIGN.md` | Quiet luxury | Warm Paper | A new object or place page, and the product has no brand guide |
| `cinematic-dark.DESIGN.md` | Cinematic dark | Night Room | A new room for one work, and the product has no brand guide |
| `precise-technical.DESIGN.md` | Precise technical | Instrument | A new list, log, or document tool, and the product has no brand guide |
| `editorial-print.DESIGN.md` | Editorial print | Column | A new essay, story, or briefing, and the product has no brand guide |

Each direction has more than one reference, which is the condition for a sample token file. The tokens still obey `taste/principles.yaml`. They are not copies of a reference palette. Night Room is not an inverted Warm Paper. Column's sheet is not the Financial Times salmon. A token file without the structural decision in the reference produces a themed skeleton. Load the reference first.

If the product has its own `DESIGN.md`, that file wins on color and type families. These examples do not override it.
